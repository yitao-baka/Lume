# Lume 视觉与可用性审查

> 基线：`main` / `09c7b00`，`src-tauri/target/release/lume.exe`
> 环境：Windows 11 build 26200，150% DPI；简体中文 / English；深色 / 浅色
> 覆盖：主窗口、导航页、剪贴板页、设置窗口、上下文菜单、清空确认框、卫星预览窗、内嵌/分离插件页
> 说明：本报告只记录审查结论，没有修改业务代码。测试设置已恢复，临时固定项已移除；
> 本机截图位于 gitignored 的 `test/visual-audit-2026-10-17/`，其中部分画面含剪贴板原文，因此不嵌入版本库。

## 结论摘要

本轮确认 9 个可复现或可由当前样式直接确认的视觉/焦点问题。最需要优先处理的是：

1. 浅色主题仍使用深色主题的亮青色强调色，活动分类、选中 chip、分组标题、链接和焦点环大面积低于可读阈值。
2. 剪贴板行内操作在未选中行上不可见，却仍进入 `Tab` 顺序；焦点会消失，连续经过多组看不到的按钮。
3. 设置窗口缩到声明的 `560×420` 最小尺寸后，「关于」导航落到固定页脚区域，鼠标命中的是页脚而不是按钮。

| 编号 | 严重度 | 区域 | 问题 |
|---|---|---|---|
| V-01 | 高 | 浅色主题 | 强调色与焦点环对比不足 |
| V-02 | 中 | 剪贴板 / 导航页 / 设置 | 次级文本与操作图标过淡、过小 |
| V-03 | 中 | 浅色主题 / 确认框 | 警告、成功、错误与危险按钮的配色未随主题调整 |
| V-04 | 高 | 剪贴板键盘导航 | 不可见行内操作仍进入焦点序列 |
| V-05 | 高 | 设置窗口 | 最小高度下「关于」导航被页脚覆盖且不可点击 |
| V-06 | 中 | 卫星预览窗 | 无关闭按钮、无标题/文件名，窗口本身没有可见出口 |
| V-07 | 中 | 模式栏 | 540px 宽度下完整隐藏最后一个模式，且没有溢出提示 |
| V-08 | 中 | 导航页 | 无图标应用回退为同一个 unknown 图标，没有按契约显示字母磁贴 |
| V-09 | 低 | 导航页 / 搜索结果 | 截断的应用名没有悬浮全文 |

## 审查方法

- 用 release 版内嵌前端启动真实 Tauri 窗口，通过 CDP 读取布局尺寸、计算样式、焦点元素和命中测试结果。
- 在 `540 / 720 / 900` 宽度，`70 / 110 / 160` 条目尺寸，深色 / 浅色，简体中文 / English 下截图比对。
- 用真实 `Input.dispatchKeyEvent` 从剪贴板分类按钮开始连续按 `Tab`，记录每一步焦点与操作层透明度。
- 用 OS 级窗口截图和像素采样复核面板表面；用 DPI-aware `MoveWindow` 将设置窗口精确缩到 `560×420`。
- 对比度按 WCAG 相对亮度公式计算；正文阈值按 `4.5:1`，大字和非文本 UI 指示按 `3:1`。

## V-01 浅色主题强调色与焦点环对比不足

**严重度：高**

### 现象

切换到浅色主题后，以下元素仍使用深色主题的 `#5ac8fa`：

- 剪贴板活动分类（例如 `All`）的文字与浅蓝底的组合；
- 外观页已选中的 `简体中文`、`浅色` chip；
- 设置页的 `外观`、`插件`、`显示` 等分组标题；
- 关于页的 GitHub 链接；
- 所有 `:focus-visible` 焦点环；
- 插件卡片里的「内置」「可分离」等 accent badge。

浅色截图中这些元素呈浅青文字落在近白或极浅青背景上，活动态明显比深色主题弱很多。焦点环同样偏淡，键盘焦点不如鼠标悬停容易识别。

### 实测对比度

以浅色 `--surface: #fbfbfd` 和活动 chip 实际底色 `rgba(90, 200, 250, 0.16)` 合成后的 `#eaf7fe` 计算：

| 组合 | 对比度 | 小字号文本阈值 |
|---|---:|---:|
| `#5ac8fa` / `#fbfbfd` | 1.83:1 | 4.5:1 |
| `#5ac8fa` / `#eaf7fe` | 1.74:1 | 4.5:1 |
| `#5ac8fa` / `#ffffff` | 1.90:1 | 4.5:1 |
| 深色主题同色 / `#1e1e20` | 8.78:1 | 4.5:1 |

同一个颜色在深色主题可用、在浅色主题不可用，说明问题不在色相本身，而在缺少按主题分层的 accent token。

### 代码依据

- `src/theme.css:13-45` 只定义了文本、边框、hover、selected 等 token，没有 accent / focus 的浅色版本。
- `src/App.css:371-374`：活动剪贴板分类直接使用 `#5ac8fa`。
- `src/App.css:1477-1490`：设置分组标题直接使用 `#5ac8fa`。
- `src/App.css:1561-1564`、`1785-1790`：chip 与链接直接使用 `#5ac8fa`。
- `src/App.css:893-903`：键盘焦点轮廓直接使用 `#5ac8fa`。

### 建议

把强调色拆成至少四个主题 token：

```css
--accent;          /* 装饰、进度、滑块 */
--accent-text;     /* 小字号文字，浅色主题必须 >= 4.5:1 */
--accent-tint;     /* 选中背景 */
--focus-ring;      /* 浅色主题必须 >= 3:1 */
```

浅色主题可先用更深的蓝色系（例如 `#0969da` 附近）做起点，再逐项验证文字、chip 背景、hover 和焦点环。深色主题可保留现有 `#5ac8fa`。

## V-02 次级文本与操作图标过淡、过小

**严重度：中**

### 现象

剪贴板条目的来源与时间、栏目标题、插件描述等第三层信息非常淡。实际截图中，`Lume · just now`、`共 169 条`、`已固定` 等文字需要靠近才能辨认。选中行右侧的复制、粘贴、删除图标也使用同一档弱色，看起来更像禁用图标。

### 实测

| 元素 | 字号 | 深色对比度 | 浅色对比度 |
|---|---:|---:|---:|
| `.clip-row-meta`（来源/时间） | 11px | 3.00:1 | 2.28:1 |
| `.result-box-desc`（插件第二行） | 10px | 4.07:1 | 3.14:1 |
| `.bar-title`（栏目标题） | 12px | 4.07:1 | 3.14:1 |
| `.clip-act`（复制/粘贴/删除） | 14px 图标 | 3.00:1 | 2.28:1 |

这些值都低于小字号正文 `4.5:1` 的目标；行内操作图标在浅色主题下也低于非文本 UI 的 `3:1` 目标。

### 代码依据

- `src/theme.css:20-21`：深色 `--text-muted` 为 `0.45`，`--text-faint` 为 `0.35`。
- `src/theme.css:37-38`：浅色对应值分别为 `0.5`、`0.38`。
- `src/App.css:512-518`：`.clip-row-meta` 使用 `font-size: 11px` 和 `--text-faint`。
- `src/App.css:1050-1055`：`.bar-title` 使用 12px 与 `--text-muted`。
- `src/App.css:1149-1156`：`.result-box-desc` 使用 10px 与 `--text-muted`。
- `src/App.css:542-556`：`.clip-act` 使用 `--text-faint`。

### 建议

- 将时间、来源、栏目标题和可操作图标提升到至少 `--text-secondary` 一档。
- 浅色 `--text-faint` 不应再用于 11px 正文；若保留弱化层级，应重新计算到 `4.5:1` 左右。
- 10px 的 provider 描述建议提升到 11–12px，或只在小尺寸以外使用。
- 对可操作图标使用专用的 `--icon-muted`，不要与纯装饰性的 faint 文本共用颜色。

## V-03 语义色与危险按钮没有按主题分层

**严重度：中**

### 现象

警告、成功、错误和危险操作使用固定的高饱和色。这些颜色在深色背景上清楚，在浅色背景上明显发白：

| 用途 | 颜色 | 浅色表面上的对比度 | 白底上的对比度 |
|---|---|---:|---:|
| 警告文字（`ffb020`） | `#ffb020` | 1.77:1 | 1.83:1 |
| 成功文字（`4cc38a`） | `#4cc38a` | 2.14:1 | 2.22:1 |
| 错误提示（`ff7b72`） | `#ff7b72` | 2.44:1 | 2.52:1 |
| 强错误（`e5484d`） | `#e5484d` | 3.79:1 | 3.91:1 |
| 白字位于 `#f87171` 危险按钮上 | `#ffffff` / `#f87171` | 2.77:1 | 2.77:1 |

剪贴板清空确认框中的红色 `Clear` 按钮就是最后一组：白字在珊瑚红上只有 2.77:1，低于普通文字阈值。

### 代码依据

- `src/App.css:828-835`：`.clip-confirm-ok` 使用 `background: #f87171; color: #fff`。
- `src/App.css:1832-1834`：`settings-hint-error` 使用 `#e5484d`。
- `src/App.css:2034-2047`：设置错误与状态错误使用 `#ff7b72`。
- `src/App.css:2210-2212`、`2343-2347`、`2463-2474`：警告、dev badge、warn/ok note 使用固定橙/绿色。

### 建议

- 增加按主题区分的 `--danger-text`、`--danger-fill`、`--warning-text`、`--success-text`。
- 危险按钮使用更深的填充色，或改用深色文字；不要用同一个珊瑚红承担深色和浅色背景。
- 错误与警告颜色至少按正文 `4.5:1` 验证，不要只靠色相表达状态。

## V-04 不可见的剪贴板行内操作仍进入焦点序列

**严重度：高**

### 复现

1. 呼出启动器，切到剪贴板页。
2. 把焦点放到任一分类按钮。
3. 连续按 `Tab`，记录 `document.activeElement` 和当前行的 `.clip-row-actions` 透明度。

### 实测

前几步依次经过分类按钮；选中行的复制、粘贴、删除按钮可见。继续按 `Tab` 后，焦点进入后续未选中行的按钮：

```json
{
  "activeClass": "clip-act",
  "ariaLabel": "Copy to clipboard",
  "rowSelected": false,
  "actionsOpacity": "0",
  "focusVisible": true
}
```

在 20 次 `Tab` 的记录中，第 10 次以后连续出现三组 `rowSelected=false / actionsOpacity=0` 的按钮。焦点环虽然被浏览器判定为 `:focus-visible`，父层透明度为 0，屏幕上没有任何可见焦点；键盘用户还要穿过大量隐藏按钮才能到「暂停记录 / 清空」。

### 代码依据

- `src/plugins/clipboard/ClipboardView.tsx:241-313`：每个虚拟行都渲染复制、粘贴、删除按钮。
- `src/App.css:528-540`：`.clip-row-actions` 默认 `opacity: 0`，只有行 hover 或 `.result-selected` 才显示；没有 `:focus-within`。
- `src/App.css:891-903`：全局焦点环只负责描边，无法让透明度为 0 的父层显形。

### 影响

- 键盘焦点不可见，用户会认为 Tab 失效。
- 按 `Enter` 会激活焦点所在的隐藏按钮，存在误粘贴或误删除风险。
- 每个渲染行贡献 3 个隐藏 tab stop，长列表的键盘成本急剧上升。

### 建议

选择一种明确的焦点契约：

- 行内出现焦点时显示操作层：`.clip-row:focus-within .clip-row-actions { opacity: 1; }`；
- 或对未选中行使用 `tabindex="-1"` / `inert`，只让当前选中行和 hover 行可聚焦；
- 或采用 roving tabindex，把每一行作为一个可聚焦单元，内部操作再按需展开。

回归测试应使用真实 `Tab` 事件并断言“焦点所在按钮的祖先操作层可见”，不能只检查 `:focus-visible`。

## V-05 设置窗口最小高度下「关于」导航被页脚覆盖

**严重度：高**

### 复现

1. 打开设置窗口，把窗口缩到声明的 `560×420` 最小内容尺寸。
2. 点击左侧「关于」。

### 实测

在 150% DPI 下把窗口内尺寸精确设为 `560×420` 后：

| 项目 | 数值 |
|---|---|
| 侧栏可见高度 | 308px |
| 侧栏内容高度 | 350px |
| 「关于」按钮范围 | y `366.67`–`402.67` |
| 内容区底边 | y `360.67` |
| 页脚顶边 | y `364.67` |

「关于」整个按钮位于内容区之外，并跨过页脚顶边。对该按钮中心点 `(79.67, 384.67)` 做命中测试，返回的是：

```text
settings-footer
```

点击没有切换页面，鼠标事件被透明页脚区域拦截。

### 代码依据

- `src-tauri/src/lib.rs:171-184`：设置窗口 `.min_inner_size(560.0, 420.0)`。
- `src/App.css:1354-1368`：`.settings-content` 与 `.settings-sidebar` 是定宽纵向 flex，侧栏没有 `overflow-y: auto`。
- `src/App.css:1436-1443`：页脚是 `flex: none`，固定在内容区之后。
- `docs/TESTING.md:196-198` 的最小窗口检查只覆盖自动化规则行，没有覆盖 9 个导航项是否仍在可见/可点击区域。

### 建议

- 让 `.settings-sidebar` 自己可滚动；或
- 把设置窗口最小高度提高到能容纳 9 个导航项和页脚的高度；或
- 在窄高度下压缩导航项，但必须保证命中区域不被页脚覆盖。

回归测试应同时断言：最后一个导航项完全位于内容区内、没有被页脚遮挡，并且真实鼠标中心点击能切换页面。

## V-06 卫星预览窗没有可见的关闭入口或标题

**严重度：中**

### 现象

剪贴板图片预览打开后，卫星窗是一个无边框、无标题栏、固定 `320×520` 的纯内容窗口。CDP 检查可见控件：

```json
{
  "viewport": { "innerWidth": 320, "innerHeight": 520 },
  "buttons": []
}
```

窗口没有文件名、媒体类型、标题栏或关闭按钮。它同时是：

- `decorations(false)`；
- `skip_taskbar(true)`；
- `set_focusable(false)`；
- 无法从任务栏或窗口自身关闭。

用户只能回到主窗口按 `Esc`，或改变当前选中行让预览消失。预览内容会遮挡工作区，且用户不知道当前预览的是哪一项。

### 代码依据

- `src-tauri/src/lib.rs:198-217`：预览窗无边框、跳过任务栏、不可激活。
- `src/preview.tsx:248-386`：预览页面只渲染内容，没有关闭按钮或标题。
- `src/preview.tsx:15` 的注释写着「× button here is the in-window close affordance」，实际 JSX 中没有这个按钮。
- `src-tauri/src/window.rs:761-765` 已有 `close_preview` 命令，但页面没有调用入口。

### 建议

- 在预览窗右上角加一个半透明关闭按钮，调用 `close_preview`。
- 增加一行极简标题（文件名 / 类型 / 来源），至少让用户知道当前预览对象。
- 保持 `WS_EX_NOACTIVATE`，按钮点击不应抢走主窗口焦点。
- 若产品决定只用 `Esc`，应提供首次使用提示，并在 `UI_GUIDELINES` 与代码注释中统一这个契约。

## V-07 模式栏隐藏溢出模式且没有可见提示

**严重度：中**

### 实测

在支持的 `540px` 宽度、English 界面、四个模式时：

| 指标 | 数值 |
|---|---:|
| 模式栏可视宽度 | 283px |
| 模式栏内容宽度 | 337px |
| 搜索框宽度 | 134.8px |
| 第四个模式 `Translate` 范围 | x `470.8`–`533.8` |
| 模式栏裁切边界 | x `482.0` |

第四个模式只剩约 11px 落在容器内，文字和图标都看不到。截图里用户看到的是三个模式，第四个模式与不存在没有区别。搜索输入框中的 `Search applications…` 也被硬裁成 `Search applic`，没有省略号。

在 540px 宽度合成 8 个长名称模式时，模式栏 `clientWidth 298`、`scrollWidth 1793`，没有任何箭头、渐隐或滚动提示。键盘切换时 `scrollIntoView` 仍能把活动项滚进视野，所以问题主要在鼠标探索与可发现性。

### 代码依据

- `src/shell/SearchBox.tsx:48-59`：通过 `scrollIntoView` 保持活动 pill 可见。
- `src/shell/SearchBox.tsx:88-138`：模式栏只渲染普通横向滚动容器。
- `src/App.css:1160-1178`：`overflow-x: auto`，但隐藏滚动条，没有边缘提示。
- `src/App.css:1181-1203`：每个模式最大 180px，超出后由容器裁切。

### 建议

- 空间不足时自动退化为仅图标，即使「仅图标」设置未开启。
- 或在模式栏两端加渐隐 / 箭头，并在最后一项露出明确的一小段。
- 或把溢出的模式收进「更多」菜单。
- 搜索框占位文字按可用宽度提供短版本，例如 `Search…`，避免英文在 540px 下被裁断。

## V-08 无图标应用没有按契约显示字母磁贴

**严重度：中**

### 现象

`UI_GUIDELINES.md` 的 Results 契约要求字母磁贴使用确定性 10 色 palette，作为真实图标的即时占位。但当前导航页在 `iconFor()` 没有返回图标时直接渲染同一个 `unknow_universal.svg`：

```tsx
<img class="result-box-img icon-unknown" src={unknownIcon} alt="" />
```

实际截图中 `BetterGI` 使用统一的 unknown 图标；在图标批量加载期间，多个应用也会短暂呈现同样的占位图，无法靠首字母区分。

### 代码依据

- `docs/UI_GUIDELINES.md:69-70`：字母磁贴契约。
- `docs/ARCHITECTURE.md:181-182`：图标按 20 个一批加载，先渲染字母磁贴再换真实图标。
- `docs/TESTING.md:87`：手工检查也要求先看到字母磁贴。
- `src/plugins/navigate/NavigateView.tsx:75-87`：fallback 只有 unknown 图标。
- `src/launcher/icons.ts:17-24`：图标缓存本身没有生成字母占位。
- `src/App.css:1015-1018`：注释仍写着“Real app icon replaces the letter tile”，但 DOM 中没有字母磁贴。

### 影响

- 首屏和图标失败时，多个应用呈现完全相同的形状，降低扫描速度。
- 文档、CSS 注释、测试说明与实现不一致。

### 建议

恢复确定性的字母/首字磁贴：

- 取应用名的首个 grapheme，避免中文、emoji、组合字符被截断；
- 以路径或名称稳定映射 10 色 palette；
- 真实图标到达后覆盖磁贴，失败时保留磁贴；
- 文件搜索结果可使用文件类型图标，与纯应用磁贴区分。

## V-09 截断的应用名没有悬浮全文

**严重度：低**

### 现象

在 900px 宽度、`entry_size = 70` 时，名称列只有约 72px，`Command Prompt`、`Windows PowerShell …`、`File Explorer`、`Registry Editor` 等都会截断。`result-box-name` 只有 ellipsis，没有 `title` 或自定义 tooltip。

同一页面的模式胶囊有 `title`，剪贴板行有 `title={item.content}`，唯独应用名和插件描述没有可恢复全文的入口，行为不一致。

### 代码依据

- `src/plugins/navigate/NavigateView.tsx:90`：`<span class="result-box-name">{item.name}</span>` 没有 title。
- `src/plugins/navigate/NavigateView.tsx:91-93`：描述 `.result-box-desc` 同样没有 title。
- `src/App.css:1140-1156`：两者均使用 ellipsis/nowrap。

### 建议

- 为名称和描述补 `title`，或在悬停/键盘选中时显示轻量 tooltip。
- 对极窄的 `70px` 条目，可为名称增加两行上限而不是单行硬截断，或把完整名称放到右键菜单标题。

## 次要观察

### 滚动位置没有替代提示

`UI_GUIDELINES` 明确要求移除滚动条，这一选择在当前视觉语言下是自洽的。但在 `560×420` 设置窗口里，插件页内容高度为 `696px`、可视高度仅 `359px`，第二张卡片刚好被页脚切断；剪贴板页也有 169 条记录但没有任何滚动位置提示。建议保留“无常驻滚动条”的契约，同时增加悬停时出现的细滚动条、顶部/底部渐隐或“还有 N 项”提示。

### 浅色主题的预览窗

预览窗按设计始终为深色，这在浏览图片、视频时是合理的中性画布。但在浅色启动器旁并排出现时，会形成很强的明暗割裂。若保持该设计，建议让预览窗的边框或背景与主窗共享一条低对比过渡；若希望完全一致，则应让预览窗跟随主题。
