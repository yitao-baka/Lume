历史条目的立项背景、实现细节与验证数据全部归档在
[docs/ROADMAP_HISTORY.md](ROADMAP_HISTORY.md)（保留原 #0–#50 编号）。

流程约定：新功能先在本文件立项，开工时升格为一条独立迭代；完成后从本文件
删除该条目，把实现/踩坑/验证写进 `ROADMAP_HISTORY.md`（编号顺延）并在
`CHANGELOG.md` 的 `[Unreleased]` 记账。「做完了」的判定以代码与 CHANGELOG 为准。

> 下方「近期候选 / 远期方向」只是排序分组，不是开发阶段——不设分期编号。

## 近期候选

### 插件生态后续

- **`.lupx` 市场源** — 静态 JSON 索引（名称/版本/下载 URL/SHA-256）+ 应用内
  安装 + 启动时版本比对提示；受仓库网络约束须可配镜像
- **浏览器 URL 获取与划词捕获** — 前台浏览器地址栏（UIA）与选中文本捕获，
  喂给插件的声明式进入规则
- **超级面板** — 光标处小窗（划词场景的 uTools 式入口）
- **`.lupx` 拖包安装与文件关联**

### 文件搜索加固

- **非 NTFS 卷**支持（当前仅固定 NTFS 卷）
- **孤立节点回收** — 目录删除后子节点残留，目前靠重建清理
- **索引持久化** — 服务重启后免全量重扫
- **服务状态实时推送** — 索引构建进度目前靠轮询 `status`
- **更丰富的搜索设置**（结果数、默认排序、引擎偏好）

### 体验与界面

- **剪贴板内容拼音搜索**（含多音字优化）
- **主窗口宽度自适应**（随列数）与**最大高度可配置**
- **栏内多行键盘导航**（最近使用/已固定等栏目条多行时的方向键行为）
- **卫星预览窗 PDF 加宽** + PDF 目录（outline）URL 选项
- **环境变量刷新的可视化** — 设置页开关 + `env-refreshed` 前端事件

### 工程治理

- **搜索源 provider 化** — 把原生索引 / 文件搜索抽成 first-party
  `SearchSource`，与插件 provider 走同一合并管线
- **剪贴板页结构重构** — 只动 `src/plugins/clipboard/` 即可落地
- **逐击键路径的异步化** — `search_apps` 等仍在主线程的命令，若输入卡顿
  按同法 `async`/`spawn_blocking` 处理

## 远期方向

- **Workflow**（编排式多步动作）
- **OCR**
- **AI 命令 / AI 宿主 API**
- **跨平台**探索（当前 Windows-only）
- **插件行模型泛化** — 任意模式自定义列表行（`PageRow` 目前是
  `AppEntry | ClipboardItem`）

## 明确不做

以下能力经权衡明确不做（保持「轻量启动器」定位），在此登记以免重复讨论：

- **Node.js 级插件执行模型** — 磁盘插件只跑标准 Web API + 沙箱桥接，
  不提供无沙箱 preload / 全量 Node 运行时
- **重型能力底座** — 不内置 ubrowser / Sharp / FFmpeg 级别的媒体与浏览器内核
- **账号与付费分发闭环** — 不做插件商店的账号、审核与付费体系；
  分发走 `.lupx` 与市场源（静态索引）
- **模拟键鼠暴露给插件** — 安全面过大；合成按键只存在于启动器内部的
  自动化与提权代理两条既定路径
